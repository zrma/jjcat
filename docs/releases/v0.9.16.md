# jjcat v0.9.16

Graph에서 bookmark와 함께 revision tag를 바로 식별하고 검색할 수 있게 한 macOS beta다.

## 지원 범위

- Apple Silicon Mac (`arm64`)
- macOS 13 이상
- Jujutsu `0.43.x`
- 로컬 저장소와 OpenSSH host alias 기반 원격 저장소

## v0.9.15에서 업데이트하기

1. 앱 시작 약 1초 뒤 또는 main window가 focus된 채 3초가 지나면 background update
   check가 실행된다. 바로 확인하려면 앱 메뉴의 **Check for Updates…**를 선택한다.
2. status bar 우측의 **Download jjcat 0.9.16**을 선택한다.
3. 다운로드와 signature 검증이 끝나 **Restart to update**가 나타날 때까지 기다린다.
4. 진행 중인 repository operation이 없는지 확인하고 **Restart to update**를 선택한다.
5. incoming `v0.9.16`이 기존 window 배치를 복원하고 macOS 전면으로 복귀한다.

자동 확인 결과 최신 버전이거나 일시적으로 실패한 경우에는 조용히 현재 작업을 유지한다.
update를 자동으로 내려받거나 강제로 재시작하지 않는다.

## 변경 사항

- Graph history의 `Refs` 열에 revision tag를 bookmark와 구분되는 녹색 read-only label로
  표시한다.
- bookmark와 tag가 같은 revision에 있어도 dense row에서 각각의 대표 label과 overflow를
  유지하며 전체 tag 이름은 hover와 접근성 label로 확인할 수 있다.
- 선택 change의 overview `Refs`에도 local/remote bookmark와 revision tag를 함께 표시한다.
- Graph 검색에서 tag 이름을 찾을 수 있다.
- tag가 붙은 revision과 인접 change를 reference-centered history folding의 기준점으로
  유지한다.
- local과 SSH repository가 같은 typed `jj` projection을 사용하며, tag metadata가 없는
  이전 projection cache도 계속 읽는다.
- tag label은 bookmark move/push drag affordance를 제공하지 않는다.
- `v0.9.15`의 transient handoff notice, non-blocking File Blame/Timeline navigation과
  signed updater path를 그대로 유지한다.

## 다운로드

수동 설치가 필요한 경우 다음 asset을 사용할 수 있다.

- `jjcat_0.9.16_aarch64.dmg`: 일반 설치용 디스크 이미지
- `jjcat_0.9.16_aarch64.app.zip`: 압축된 앱 번들
- `jjcat_0.9.16_aarch64.app.tar.gz`: 서명된 updater archive
- `jjcat_0.9.16_aarch64.app.tar.gz.sig`: updater archive의 Tauri Minisign signature
- `latest-beta.json`: beta updater manifest
- `SHA256SUMS`: 모든 release asset의 다운로드 체크섬

같은 디렉터리에서 다음 명령으로 다운로드를 검증할 수 있다.

```sh
shasum -a 256 -c SHA256SUMS
```

## 서명 및 Gatekeeper 경계

Updater archive는 Tauri Minisign signature를 필수로 검증한다. macOS app 자체는 번들
무결성을 위해 ad-hoc 서명했지만 Apple Developer ID로 서명하거나 Apple에
notarization하지 않았다. 수동 설치 시 Gatekeeper가 차단하면 Finder의 **열기** 또는
**시스템 설정 → 개인정보 보호 및 보안 → 확인 없이 열기**를 사용한다. Gatekeeper를
끄거나 quarantine 속성을 제거할 필요는 없다.

## 알려진 제한

- tag 생성, 삭제 또는 이동 action은 제공하지 않는다.
- annotated tag message와 tag target metadata는 별도 viewer로 표시하지 않는다.
- file history는 선택 revision의 ancestors 중 최대 200개로 제한된다.
- rename/copy 이전 path를 추적하는 cross-path history는 제공하지 않는다.
- Intel Mac용 빌드는 제공하지 않는다.
- Developer ID 서명과 notarization을 제공하지 않는다.
- beta update는 자동 다운로드나 강제 재시작을 하지 않는다.
- 원격 저장소는 비대화형 OpenSSH 접속과 원격 `jj` 설치가 필요하다.

문제가 있으면 [GitHub Issues](https://github.com/zrma/jjcat/issues)에 재현 절차를
남겨 달라.
