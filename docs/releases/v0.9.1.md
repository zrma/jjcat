# jjcat v0.9.1

jjcat의 첫 updater-enabled macOS beta다. 우하단 status bar에 새 버전이 있을 때만
download action을 표시하고, 서명된 update를 내려받아 검증한 뒤 사용자가 선택할 때
재시작한다.

## 지원 범위

- Apple Silicon Mac (`arm64`)
- macOS 13 이상
- Jujutsu `0.43.x`
- 로컬 저장소와 OpenSSH host alias 기반 원격 저장소

## v0.9.0에서 설치하기

`v0.9.0`에는 updater가 없으므로 이 버전은 DMG를 내려받아 한 번 수동으로 설치해야
한다.

1. 실행 중인 jjcat을 종료한다.
2. `jjcat_0.9.1_aarch64.dmg`를 열고 `jjcat.app`을 Applications 폴더로 복사해 기존
   앱을 교체한다.
3. Finder에서 교체한 `jjcat.app`을 Control-클릭한 뒤 **열기**를 선택한다.

같은 application identifier와 app-data location을 사용하므로 기존 repository registry와
안전한 사용자 설정은 유지된다. 이후 새 beta가 게시되면 jjcat에서 직접 업데이트할 수
있다.

## 인앱 업데이트

- 새 버전이 있을 때만 status bar 우측에 `Download jjcat <version>`이 나타난다.
- 다운로드 진행률과 서명 검증 상태를 같은 위치에서 확인할 수 있다.
- 설치가 준비돼도 자동으로 재시작하지 않는다. `Restart to update`를 선택해야
  재시작한다.
- 진행 중인 repository operation이 있으면 종료될 때까지 재시작 action을 비활성화한다.
- 앱 메뉴의 **Check for Updates…**에서 수동으로 다시 확인할 수 있다.

## 다운로드

- `jjcat_0.9.1_aarch64.dmg`: 일반 설치용 디스크 이미지
- `jjcat_0.9.1_aarch64.app.zip`: 압축된 앱 번들
- `jjcat_0.9.1_aarch64.app.tar.gz`: 서명된 updater archive
- `jjcat_0.9.1_aarch64.app.tar.gz.sig`: updater archive의 Tauri Minisign signature
- `latest-beta.json`: beta updater manifest
- `SHA256SUMS`: 모든 release asset의 다운로드 체크섬

같은 디렉터리에서 다음 명령으로 다운로드를 검증할 수 있다.

```sh
shasum -a 256 -c SHA256SUMS
```

## 서명 및 처음 실행 경계

Updater archive는 jjcat에 내장된 public key와 일치하는 Tauri Minisign signature를
필수로 검증한다. 이 beta의 macOS app 자체는 번들 무결성을 위해 ad-hoc
서명했지만 Apple Developer ID로 서명하거나 Apple에 notarization하지 않았다.
따라서 macOS Gatekeeper가 처음 교체한 앱의 실행을 차단할 수 있다.

Finder의 **열기** 경로로 실행할 수 없다면 **시스템 설정 → 개인정보 보호 및 보안**에서
차단된 jjcat 항목의 **확인 없이 열기**를 선택한다. Gatekeeper를 끄거나 quarantine
속성을 제거할 필요는 없다.

## 알려진 제한

- Intel Mac용 빌드는 제공하지 않는다.
- Developer ID 서명과 notarization을 제공하지 않는다.
- `v0.9.0`은 이 버전을 자동으로 발견하거나 설치할 수 없다.
- beta update는 자동으로 내려받거나 강제로 재시작하지 않는다.
- 원격 저장소는 비대화형 OpenSSH 접속과 원격 `jj` 설치가 필요하다.

중요한 저장소 변경은 preview와 exact target을 확인한 뒤 실행하고, 문제가 있으면
[GitHub Issues](https://github.com/zrma/jjcat/issues)에 재현 절차를 남겨 달라.
