# jjcat v0.9.15

Repository/file handoff와 path copy 성공 문구가 작업 상태처럼 영구 잔류하지 않고 짧게
표시된 뒤 자동으로 정리되도록 수정한 macOS beta다.

## 지원 범위

- Apple Silicon Mac (`arm64`)
- macOS 13 이상
- Jujutsu `0.43.x`
- 로컬 저장소와 OpenSSH host alias 기반 원격 저장소

## v0.9.14에서 업데이트하기

1. 앱 시작 약 1초 뒤 또는 main window가 focus된 채 3초가 지나면 background update
   check가 실행된다. 바로 확인하려면 앱 메뉴의 **Check for Updates…**를 선택한다.
2. status bar 우측의 **Download jjcat 0.9.15**를 선택한다.
3. 다운로드와 signature 검증이 끝나 **Restart to update**가 나타날 때까지 기다린다.
4. 진행 중인 repository operation이 없는지 확인하고 **Restart to update**를 선택한다.
5. incoming `v0.9.15`가 기존 window 배치를 복원하고 macOS 전면으로 복귀한다.

자동 확인 결과 최신 버전이거나 일시적으로 실패한 경우에는 조용히 현재 작업을 유지한다.
update를 자동으로 내려받거나 강제로 재시작하지 않는다.

## 변경 사항

- repository의 **Open in VS Code**와 **Open terminal**, 파일의 **Open in VS Code**와
  **Show in Finder**, **Copy Path** 성공 feedback을 4초 뒤 자동으로 숨긴다.
- 같은 action과 같은 path를 연속 실행해도 마지막 실행부터 4초를 다시 계산한다.
- 이전 action의 만료 이벤트가 더 최신 notice를 지우지 않도록 sequence를 확인한다.
- app/window가 종료되거나 notice가 교체되면 기존 timer를 정리한다.
- repository error, recovery, refresh waiting, mutation activity처럼 지속 상태를 나타내는
  notice lifecycle은 변경하지 않는다.
- native Finder/VS Code/terminal launch, clipboard와 local/SSH transport contract는
  변경하지 않는다.
- `v0.9.14`의 non-blocking File Blame/Timeline navigation, calendar ruler와 signed updater
  path를 그대로 유지한다.

## 다운로드

수동 설치가 필요한 경우 다음 asset을 사용할 수 있다.

- `jjcat_0.9.15_aarch64.dmg`: 일반 설치용 디스크 이미지
- `jjcat_0.9.15_aarch64.app.zip`: 압축된 앱 번들
- `jjcat_0.9.15_aarch64.app.tar.gz`: 서명된 updater archive
- `jjcat_0.9.15_aarch64.app.tar.gz.sig`: updater archive의 Tauri Minisign signature
- `latest-beta.json`: beta updater manifest
- `SHA256SUMS`: 모든 release asset의 다운로드 체크섬

같은 디렉터리에서 다음 명령으로 다운로드를 검증할 수 있다.

```sh
shasum -a 256 -c SHA256SUMS
```

## 서명 및 Gatekeeper 경계

Updater archive는 Tauri Minisign signature를 필수로 검증한다. macOS app 자체는 번들
무결성을 위해 ad-hoc 서명했지만 Apple Developer ID로 서명하거나 Apple에
notarization하지 않았다. 수동 설치 시 Gatekeeper가 차단하면 Finder의 **열기** 또는
**시스템 설정 → 개인정보 보호 및 보안 → 확인 없이 열기**를 사용한다. Gatekeeper를
끄거나 quarantine 속성을 제거할 필요는 없다.

## 알려진 제한

- success notice는 최근 한 건만 표시하며 별도 notification history를 제공하지 않는다.
- file history는 선택 revision의 ancestors 중 최대 200개로 제한된다.
- rename/copy 이전 path를 추적하는 cross-path history는 제공하지 않는다.
- Intel Mac용 빌드는 제공하지 않는다.
- Developer ID 서명과 notarization을 제공하지 않는다.
- beta update는 자동 다운로드나 강제 재시작을 하지 않는다.
- 원격 저장소는 비대화형 OpenSSH 접속과 원격 `jj` 설치가 필요하다.

문제가 있으면 [GitHub Issues](https://github.com/zrma/jjcat/issues)에 재현 절차를
남겨 달라.
