# jjcat v0.9.13

File Blame/Timeline의 단순 range slider를 실제 file history의 시간 분포와 commit을 직접
읽고 탐색할 수 있는 calendar ruler로 교체한 macOS beta다.

## 지원 범위

- Apple Silicon Mac (`arm64`)
- macOS 13 이상
- Jujutsu `0.43.x`
- 로컬 저장소와 OpenSSH host alias 기반 원격 저장소

## v0.9.12에서 업데이트하기

1. 앱 시작 약 1초 뒤 또는 main window가 focus된 채 3초가 지나면 background update
   check가 실행된다. 바로 확인하려면 앱 메뉴의 **Check for Updates…**를 선택한다.
2. status bar 우측의 **Download jjcat 0.9.13**을 선택한다.
3. 다운로드와 signature 검증이 끝나 **Restart to update**가 나타날 때까지 기다린다.
4. 진행 중인 repository operation이 없는지 확인하고 **Restart to update**를 선택한다.
5. incoming `v0.9.13`이 기존 window 배치를 복원하고 macOS 전면으로 복귀한다.

자동 확인 결과 최신 버전이거나 일시적으로 실패한 경우에는 조용히 현재 작업을 유지한다.
update를 자동으로 내려받거나 강제로 재시작하지 않는다.

## 변경 사항

- File Blame/Timeline 상단의 균등 index range를 실제 commit timestamp에 비례하는 연·월
  calendar ruler로 교체했다.
- month tick과 year label, 선택 revision cursor, file history의 commit marker를 함께
  표시해 긴 기간의 변경 분포를 한눈에 읽을 수 있다.
- marker를 hover하거나 keyboard focus하면 commit summary, author, absolute timestamp와
  short commit ID를 상단 preview strip에 표시한다.
- singleton marker는 click 한 번으로 해당 revision으로 이동한다. 화면상 가까운 commit은
  count marker로 묶고 click하면 각 revision을 선택할 수 있는 compact picker를 연다.
- marker clustering은 window width에 반응하며 native minimum 820px에서도 picker를 화면
  안에 유지한다.
- 기존 revision select, older/newer button, Arrow Left/Right와 line provenance navigation은
  그대로 유지한다.
- local/SSH driver와 ancestry-bounded 200-entry file history contract는 변경하지 않는다.
- `v0.9.12`의 revision File Tree/source, file context actions, foreground activation,
  window/splitter 복원과 signed updater path를 그대로 유지한다.

## 다운로드

수동 설치가 필요한 경우 다음 asset을 사용할 수 있다.

- `jjcat_0.9.13_aarch64.dmg`: 일반 설치용 디스크 이미지
- `jjcat_0.9.13_aarch64.app.zip`: 압축된 앱 번들
- `jjcat_0.9.13_aarch64.app.tar.gz`: 서명된 updater archive
- `jjcat_0.9.13_aarch64.app.tar.gz.sig`: updater archive의 Tauri Minisign signature
- `latest-beta.json`: beta updater manifest
- `SHA256SUMS`: 모든 release asset의 다운로드 체크섬

같은 디렉터리에서 다음 명령으로 다운로드를 검증할 수 있다.

```sh
shasum -a 256 -c SHA256SUMS
```

## 서명 및 Gatekeeper 경계

Updater archive는 Tauri Minisign signature를 필수로 검증한다. macOS app 자체는 번들
무결성을 위해 ad-hoc 서명했지만 Apple Developer ID로 서명하거나 Apple에
notarization하지 않았다. 수동 설치 시 Gatekeeper가 차단하면 Finder의 **열기** 또는
**시스템 설정 → 개인정보 보호 및 보안 → 확인 없이 열기**를 사용한다. Gatekeeper를
끄거나 quarantine 속성을 제거할 필요는 없다.

## 알려진 제한

- file history는 선택 revision의 ancestors 중 최대 200개로 제한된다.
- rename/copy 이전 path를 추적하는 cross-path history는 제공하지 않는다.
- marker cluster는 화면상 가까운 revision을 묶으며 repository history 자체를 변경하지 않는다.
- file edit/save 또는 arbitrary revision restore는 제공하지 않는다.
- Intel Mac용 빌드는 제공하지 않는다.
- Developer ID 서명과 notarization을 제공하지 않는다.
- beta update는 자동 다운로드나 강제 재시작을 하지 않는다.
- 원격 저장소는 비대화형 OpenSSH 접속과 원격 `jj` 설치가 필요하다.

문제가 있으면 [GitHub Issues](https://github.com/zrma/jjcat/issues)에 재현 절차를
남겨 달라.
