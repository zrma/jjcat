# jjcat v0.9.14

File Blame/Timeline의 revision 전환 중 기존 line provenance를 유지하고, 가까운 revision을
미리 읽어 탐색 흐름을 빠르게 만든 macOS beta다.

## 지원 범위

- Apple Silicon Mac (`arm64`)
- macOS 13 이상
- Jujutsu `0.43.x`
- 로컬 저장소와 OpenSSH host alias 기반 원격 저장소

## v0.9.13에서 업데이트하기

1. 앱 시작 약 1초 뒤 또는 main window가 focus된 채 3초가 지나면 background update
   check가 실행된다. 바로 확인하려면 앱 메뉴의 **Check for Updates…**를 선택한다.
2. status bar 우측의 **Download jjcat 0.9.14**를 선택한다.
3. 다운로드와 signature 검증이 끝나 **Restart to update**가 나타날 때까지 기다린다.
4. 진행 중인 repository operation이 없는지 확인하고 **Restart to update**를 선택한다.
5. incoming `v0.9.14`가 기존 window 배치를 복원하고 macOS 전면으로 복귀한다.

자동 확인 결과 최신 버전이거나 일시적으로 실패한 경우에는 조용히 현재 작업을 유지한다.
update를 자동으로 내려받거나 강제로 재시작하지 않는다.

## 변경 사항

- 첫 File Blame/Timeline load에는 기존 중앙 loading state를 유지한다.
- revision을 이동한 뒤에는 기존 text, binary 또는 empty projection을 그대로 보여주면서
  compact activity를 겹쳐 표시하고, 새 projection이 준비되면 한 번에 교체한다.
- 새 revision 조회가 실패해도 직전 projection을 유지하고 현재 표시 중인 commit을
  명시한다.
- window lifetime에 한정된 5-entry bounded LRU cache를 추가하고 같은 revision의 동시
  조회를 하나로 합친다.
- 현재 revision의 immediate older/newer revision을 best-effort로 선로딩해 인접 탐색은
  가능한 경우 busy state 없이 즉시 전환한다.
- 선로딩 실패는 현재 화면을 경고 상태로 바꾸지 않으며, 실제 foreground 선택 시에만
  오류를 표시한다.
- local/SSH driver, ancestry-bounded 200-entry file history와 persistent storage contract는
  변경하지 않는다.
- `v0.9.13`의 calendar ruler, marker preview/cluster navigation, revision File Tree/source와
  signed updater path를 그대로 유지한다.

## 다운로드

수동 설치가 필요한 경우 다음 asset을 사용할 수 있다.

- `jjcat_0.9.14_aarch64.dmg`: 일반 설치용 디스크 이미지
- `jjcat_0.9.14_aarch64.app.zip`: 압축된 앱 번들
- `jjcat_0.9.14_aarch64.app.tar.gz`: 서명된 updater archive
- `jjcat_0.9.14_aarch64.app.tar.gz.sig`: updater archive의 Tauri Minisign signature
- `latest-beta.json`: beta updater manifest
- `SHA256SUMS`: 모든 release asset의 다운로드 체크섬

같은 디렉터리에서 다음 명령으로 다운로드를 검증할 수 있다.

```sh
shasum -a 256 -c SHA256SUMS
```

## 서명 및 Gatekeeper 경계

Updater archive는 Tauri Minisign signature를 필수로 검증한다. macOS app 자체는 번들
무결성을 위해 ad-hoc 서명했지만 Apple Developer ID로 서명하거나 Apple에
notarization하지 않았다. 수동 설치 시 Gatekeeper가 차단하면 Finder의 **열기** 또는
**시스템 설정 → 개인정보 보호 및 보안 → 확인 없이 열기**를 사용한다. Gatekeeper를
끄거나 quarantine 속성을 제거할 필요는 없다.

## 알려진 제한

- file history는 선택 revision의 ancestors 중 최대 200개로 제한된다.
- rename/copy 이전 path를 추적하는 cross-path history는 제공하지 않는다.
- projection cache와 neighbor prefetch는 Blame/Timeline window를 닫으면 사라진다.
- file edit/save 또는 arbitrary revision restore는 제공하지 않는다.
- Intel Mac용 빌드는 제공하지 않는다.
- Developer ID 서명과 notarization을 제공하지 않는다.
- beta update는 자동 다운로드나 강제 재시작을 하지 않는다.
- 원격 저장소는 비대화형 OpenSSH 접속과 원격 `jj` 설치가 필요하다.

문제가 있으면 [GitHub Issues](https://github.com/zrma/jjcat/issues)에 재현 절차를
남겨 달라.
