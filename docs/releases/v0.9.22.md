# jjcat v0.9.22

200개보다 오래된 히스토리를 추가로 불러오고 탐색 위치를 유지하는 macOS beta다.

## 지원 범위

- Apple Silicon Mac (`arm64`)
- macOS 13 이상
- Jujutsu `0.43.x`
- 로컬 저장소와 OpenSSH host alias 기반 원격 저장소

## v0.9.21에서 업데이트하기

1. 앱 시작 약 1초 뒤 또는 main window가 focus된 채 3초가 지나면 background update
   check가 실행된다. 바로 확인하려면 앱 메뉴의 **Check for Updates…**를 선택한다.
2. status bar 우측의 **Download jjcat 0.9.22**을 선택한다.
3. 다운로드와 signature 검증이 끝나 **Restart to update**가 나타날 때까지 기다린다.
4. 진행 중인 repository operation이 없는지 확인하고 **Restart to update**를 선택한다.
5. incoming `v0.9.22`이 기존 window 배치를 복원하고 macOS 전면으로 복귀한다.

자동 확인 결과 최신 버전이거나 일시적으로 실패한 경우에는 조용히 현재 작업을 유지한다.
update를 자동으로 내려받거나 강제로 재시작하지 않는다.

## 변경 사항

- 초기 200개를 표시하고 graph 하단의 **Load older history**로 최대 200개씩 더 읽는다.
- 로딩 개수와 이전 기록 존재 여부를 표시하며 끝에 도달하면 **All history loaded**를 표시한다.
- **Show more**와 **Show all**은 로딩된 구간을 펼치고, **Load older history**는 더 오래된 데이터를 조회한다.
- 추가 로딩과 같은 저장소 시점의 새로고침에서 선택·스크롤·펼침을 유지한다.
- 마지막 page까지 읽어도 추가 로딩 버튼의 키보드 포커스를 유지한다.
- 여러 브랜치와 merge 기록을 동일한 저장소 시점에서 중복·누락 없이 이어 읽는다.
- 검색이 로딩된 기록을 대상으로 한다는 안내를 표시한다. 검색 결과가 없어도 이전 기록을 더 읽을 수 있다.
- 로컬·SSH 모두 요청별 출력 크기·시간 제한과 취소 기능을 유지한다.

## 다운로드

수동 설치가 필요한 경우 다음 asset을 사용할 수 있다.

- `jjcat_0.9.22_aarch64.dmg`: 일반 설치용 디스크 이미지
- `jjcat_0.9.22_aarch64.app.zip`: 압축된 앱 번들
- `jjcat_0.9.22_aarch64.app.tar.gz`: 서명된 updater archive
- `jjcat_0.9.22_aarch64.app.tar.gz.sig`: updater archive의 Tauri Minisign signature
- `latest-beta.json`: beta updater manifest
- `SHA256SUMS`: 모든 release asset의 다운로드 체크섬

같은 디렉터리에서 다음 명령으로 다운로드를 검증할 수 있다.

```sh
shasum -a 256 -c SHA256SUMS
```

## 서명 및 Gatekeeper 경계

Updater archive는 Tauri Minisign signature를 필수로 검증한다. macOS app 자체는 번들
무결성을 위해 ad-hoc 서명했지만 Apple Developer ID로 서명하거나 Apple에
notarization하지 않았다. 수동 설치 시 Gatekeeper가 차단하면 Finder의 **열기** 또는
**시스템 설정 → 개인정보 보호 및 보안 → 확인 없이 열기**를 사용한다. Gatekeeper를
끄거나 quarantine 속성을 제거할 필요는 없다.

## 알려진 제한

- 검색은 현재 로딩된 기록만 대상으로 하며 저장소 전체 검색은 제공하지 않는다.
- 저장소 operation이 변경되면 새로고침은 새 시점의 첫 200개로 전환한다.
- 펼침 상태는 저장소 시점·filter 변경 시 초기화되며 앱 재시작 간에는 저장하지 않는다.
- 누적 로딩에 따라 cache 메모리와 graph 계산 비용이 증가한다. 매우 넓은 분기나 큰 출력이
  요청별 안전 예산을 초과하면 기존 기록을 유지하고 오류를 표시한다.
- Intel Mac용 빌드는 제공하지 않는다.
- Developer ID 서명과 notarization을 제공하지 않는다.
- beta update는 자동 다운로드나 강제 재시작을 하지 않는다.
- 원격 저장소는 비대화형 OpenSSH 접속과 원격 `jj` 설치가 필요하다.

문제가 있으면 [GitHub Issues](https://github.com/zrma/jjcat/issues)에 재현 절차를
남겨 달라.
